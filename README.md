# ClimbLog production starter

これまでの画面（カレンダー・記録編集・ジムごとのグレード設定・統計）を引き継いだ個人用Webアプリです。Supabase Authでログインし、記録をアカウント専用のPostgres行に保存します。iPhone/PC対応です。

## Supabaseの準備
1. SupabaseでFree projectを作成します。
2. SQL Editorで `supabase/schema.sql` を実行し、保存テーブルとRLSアクセス制御を作成します。
3. Authentication > URL Configurationに公開後のGitHub Pages URLを登録します。
4. `config.example.js` を `config.js` にコピーし、Project URLとPublishable keyを設定します。Secret/service_role keyはブラウザー側に置かないでください。

## GitHub Pagesへ公開
1. GitHubリポジトリにフォルダー内のファイルを登録してmainへpushします。
2. Settings > PagesでGitHub Actionsを選択します。同梱workflowが公開します。
3. Pages URLをSupabaseのURL Configurationにも許可URLとして追加します。
4. アプリでアカウントを作成し、確認メールから戻ってログインします。同じアカウントでスマホとPCから使えます。

PrivateリポジトリでもPagesのサイトURLは公開扱いです。記録データはログインとRLSで本人のアカウントに制限されます。

## バックアップと無料枠
ヘッダーの「書き出し」からJSONを定期保存してください。Supabase Freeのデータベースは500MBで、超過すると読み取り専用になることがあります。利用の少ないFree projectは一時停止される場合があります。写真・動画は保存せず、記録はテキスト中心です。

この初期版はアカウントごとにJSONBデータを1行で保存します。長期間の大量記録では同期データが大きくなるため、必要になった時点で記録を1件ずつの行に分割する移行が必要です。

既存プロトタイプのローカル記録は自動移行しません。ログイン後のデータ混在を防ぐため、新しいアカウントは空の状態から開始します。

## フォルダー構成
- index.html: 画面のHTMLとスタイル
- assets/js/: 画面操作とクラウド同期
- supabase/schema.sql: Supabaseのテーブルとアクセス制御
- docs/data-model.json: 記録データの構造
- .github/workflows/: GitHub Pagesの公開設定
- config.js: Supabase接続設定（Publishable keyのみ）

## 開発中の機能
- 最大出力測定：ハングボード保持、地面からの片手リフト（左右別）、加重懸垂を記録し、握り方・持ち手厚などの条件ごとに推移と自己ベストを表示します。通常トレーニングは重複を整理した種目リストから選びます。
- 記録検索：活動種別とキーワードで検索します。
- 目標：目指したい登り、次に試すこと、進み具合や気づきを文章で保存します。状態は挑戦中・見直し中・達成から本人が選びます。回数目標・自動達成率は使いません。
- 設定：ライト／ダーク／端末テーマ、週の開始曜日、ジム設定、JSONバックアップ、ログアウトを管理します。設定はクラウドに同期します。
- 身体情報：身長・リーチ（両手の指先間）をcm単位で保存し、体重は日付別の履歴とグラフで管理します。身体情報はクラウド同期とJSONバックアップの対象です。
- ジム記録：既定の完登に加えて「敗退」を記録できます。ジム課題と通常トレーニングは、同じ日付・場所の複数項目をまとめて保存できます。

## ローカルテスト
Node.jsを使い、追加した集計ロジックを次のコマンドで確認できます。

```powershell
node --test tests/*.test.mjs
```

開発ブランチの画面で実際に保存動作を確認するときは、本番アカウントではなく開発用Supabase Authユーザーでログインしてください。

複数入力では追加済みの項目を「編集」から呼び出し、更新・編集取消・削除できます。同じ種目も別々の項目として何度でも追加できます。保存はリスト全体を一度に行います。

旧プロジェクト機能は廃止しました。過去のクライミング記録を残し、紐付けを解除します。旧結果「プロジェクト」は「トライのみ」に移行し、メモ・日付・グレードは保持します。

## 記録を続けやすくする機能
- 前回コピー：ジムは選択したジムの前回日、通常トレーニングは前回日の種目一覧を呼び出します。最大出力は同じ測定種目・左右の前回値を入力欄へ呼び出します。新しい日付の体重を使い、保存済みの記録は変更しません。
- 下書き：入力欄・追加済み項目・編集中の項目をこのブラウザーに自動保存します。日付と編集対象、ログインアカウントを分けて復元できます。「閉じる」で残し、「破棄」で消します。下書きはクラウド同期やJSONバックアップには含めず、ブラウザーの保存データを削除すると消えます。
- 最大出力：同じ測定種目・握り方・厚さ・保持時間で推移を比較します。体重比は記録時の体重を使用します。片手リフトの左右差は同日・同条件の最大値を比較し、差率は重量差を大きい方の重量で割って表示します。体重や片側の測定が未記録の場合は比率・左右差を推定しません。
- 日別まとめ：カレンダーの日付詳細でトレーニングをまとめ、通常種目のセット数・回数・時間と測定件数を分けて集計します。ジムもジム別に完登・敗退・トライをまとめます。展開後は各記録を編集・削除できます。

## ベースキャンプと画面改善
- 起動時はゲーム風のホームを表示します。文章の目標、条件別の自己ベスト、冒険のしるし、最近の記録を振り返れます。しるしは保存済みの記録から計算し、訪問ノルマや連続記録ペナルティは設けません。
- ホームから今日の記録追加、カレンダー、統計、目標編集へ移動できます。カレンダーと統計もタブで引き続き開けます。
- 身体情報の保存ボタンは一つです。身長・リーチと、必要なら指定日の体重をまとめて保存します。体重が空欄の場合は過去の履歴を保持します。
- カレンダーでは今日の数字を強調し、選択中の日付とは別に識別できます。「今日」ボタンで今月・今日の記録に戻れます。
- ライトモードのトレーニング量は、淡い背景・濃い文字・紫のアクセントを使用します。
- 旧来の数値の回数目標は、新しい文章へ自動変換しません。クライミング記録そのものは保持します。

## ドット絵のホームと追加機能（2026-10-25）
- ホームのオリジナルキャラクター「コハク」は、山小屋で過ごします。話しかけると登り、記録保存で喜び、振り返り保存でノートに向かい、休憩タイマー中はくつろぎます。動きを減らす端末設定に対応します。訪問ノルマはありません。
- 通常トレーニングの「セットごとに詳しく記録」で重量・回数・保持秒数をセット別に入力できます。追加済みの種目・過去記録・下書き・前回コピーにも対応します。集計は実際のセット別回数を使います。
- 「お気に入りメニュー」は、追加済みの通常種目を名前付きで保存します。呼び出すと保存前リストに入り、各項目を編集してから登録できます。過去の日付・ID・体重はコピーしません。
- 最大出力の「測定条件のプリセット」で握り方・厚さ・保持時間などを保存できます。結果の重量は保存しません。片手リフトは「左右まとめて」で左右の重量を一度に入力し、左右別の記録を生成します。片手リフトの負荷には体重を加算しません。
- ホームとカレンダーから、日付別の睡眠・元気度・疲労・指の状態・今日の気づき・次に試すことを保存できます。今日の振り返りはホームにも表示します。
- 休憩タイマーはプリセットと任意秒数、一時停止・再開、任意の終了音に対応します。絶対時刻で残り時間を計算し、再読み込みでも復元します。バックグラウンド通知音の保証はありません。
- 設定の「データ管理」からJSONを復元できます。25MB以下、形式を検証し、件数と重複を確認して適用します。既定は現在の同一ID・日付の内容を維持し、上書き・身体/目標/表示設定の復元は明示選択です。上書きした記録は編集履歴に残します。
- 削除した活動記録はゴミ箱から元のIDで復元できます。編集履歴から変更前の内容にも戻せます。完全削除は確認後、その記録の関連履歴も削除します。ゴミ箱は自動では空にしません。
- 新しいプリセット・メニュー・振り返り・履歴・ゴミ箱は、既存の `user_app_state.payload` に同期します。追加のSupabaseテーブルやSQL移行は不要です。下書きとタイマーは端末内のみです。
- PWAのホーム画面追加に対応しました。設定の「ホーム画面に追加」から案内を表示します。iPhoneはSafariの共有メニューを使用します。HTTPSまたはlocalhostで動作し、GitHub Pagesのサブパスに対応します。認証・同期はオンライン前提です。Service Workerは同一オリジンの静的画面のみをキャッシュし、Supabaseや認証付きリクエストをキャッシュしません。更新がある場合は入力を保存してから更新ボタンを押してください。
- 不要と指定されたムーブタグ・動画リンク・ホームのカスタマイズ操作は追加していません。

実装は `assets/js/training-studio.js`（入力）、`life-tools.js`（日誌・タイマー・復元UI）、各 `*-model.mjs`（集計・履歴・検証）、`pixel-companion.mjs`（描画）に分けています。外部の描画ライブラリは不要です。

追加分の検証は `docs/pixel-life-verification.md` を参照してください。
