# 日次保守と期間検索（2026-11-02）

## 採用した新機能
カレンダーの「記録を探す」で開始日・終了日を指定できるようにした。片方だけ、同じ日、キーワード・活動種別との組み合わせに対応。期間変更時は表示を30件に戻し、解除すると期間を含む全条件を戻す。開始日が終了日より後なら理由を表示する。検索は表示だけを変え、保存記録やクラウドの形式は変えない。外部送信・課金・依存の追加なし。

## 最新動向と選択理由
2026-11-02に次の公式情報を確認した。
- https://www.crimpd.com/blog/summer-2026-updates/ （2026-08-27公開）：記録操作と履歴の充実。既存のClimbLogにもセット実行・体重履歴があるため、重複機能を追加しない。
- https://www.crimpd.com/docs/getting-started/ ：期間を調整できるトレーニング履歴を提供している。ClimbLogの検索は文章と活動種別のみだったため、特定期間の記録を探す機能を採用した。これが新しい業界標準だとは主張しない。
データ出力拡張やソーシャル共有も候補だが、既存JSON出力との重複、個人情報の送信範囲、利用効果の不確実さを考え今回は見送った。

## 検証
- 単体テスト313件成功。期間の両端、片側のみ、同日、うるう日、不正日付、逆順、活動・文章検索との組み合わせ、元データを変えないことを確認。
- 新規画面テスト：320/390/1280px、ライト・ダーク。検索、条件解除、逆順エラー、追加表示のリセット、画面はみ出しなし、記録データ不変、実行エラーなし。320pxの画面画像も目視確認。
- 既存record-viewとpwa-upgradeの画面テスト成功。閲覧・編集・再実行・ゴミ箱、入力を守る更新案内、更新後の保存データ保持・旧キャッシュ除去を確認。
- 本番の新規ブラウザーでログイン画面有効、主要5資源HTTP 200、横はみ出し・実行エラーなしを変更前に確認。
- 全てサンプルとモック。本番アカウント、実記録、AI APIをテスト操作していない。
