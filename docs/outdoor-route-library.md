# 外岩の課題一覧

ホーム下部の「外岩の課題」から開く。端末内の「登りたい課題」、課題名付きの外岩記録、写真・トポの紐付けをまとめた、自分用の一覧。外部の課題データベースは使用しない。

## 操作

- 岩場・検索語・「すべて／登りたい／挑戦中／完登」で絞り込む。検索は空白区切りで全ての語を含む課題を表示する。
- 開き直すと絞り込みを解除して先頭に戻る。30課題ずつ表示し、追加表示できる。詳細から戻ると一覧の位置を保持する。
- 課題を開くと、記録がある日数・完登日数、写真・トポ、実施履歴を確認できる。同日の複数記録を複数日として数えない。
- 「この課題を記録」から従来の入力画面へ進む。岩場・課題・グレードを引き継ぎ、過去の結果やメモを新しい実績としてコピーしない。入力中の下書きは課題別に分ける。
- 履歴をタップすると従来の詳細・編集・削除を利用できる。実施記録の削除は従来のごみ箱へ移す方式を維持する。
- 星は「登りたい」への追加・解除。既存の優先設定は、詳細の「優先して取り組む」で維持する。優先課題、最近の記録、名前の順で表示する。
- 新しく追加した課題は「登りたい」に入る。外しても実施記録・写真は削除しない。それらがない課題は一覧から外れる。

## データの扱い

`outdoor-route-library.mjs` は既存データを読み取って一覧を作るだけで、移行や一括書き換えを行わない。バックアップ・復元は既存の記録、課題リスト、写真の仕組みを引き継ぐ。

岩場・エリア・課題名・ボルダー／リードの組み合わせで分ける。エリア未設定の課題から記録時にエリアを追加した場合は、既存の明示的な `outdoorWishId` と名前が一致するときだけ関連付ける。異なる岩場や種目を名前だけで統合しない。

完登は既存の完登結果がある課題。挑戦中は、完登記録がなく敗退またはトライ数が記録されている課題。結果とトライが未設定の記録を敗退と断定しない。削除・編集・復元後は現在の実施記録から再計算する。

グレードは最近の記録を優先して表示し、過去の表記は各履歴に残す。豊田式を段級へ換算しない。岩場・課題名が不足した記録はカレンダーで参照できる旨を一覧に表示する。

写真は端末内のIndexedDBから、見える範囲のサムネイルを読み込む。画面切り替えや閉じたときに一時URLを解放する。外部送信やクラウド連携は追加しない。

## 検証

- 単体：`node --test tests/outdoor-route-library.test.mjs tests/outdoor-wishlist.test.mjs`
- 画面：`tests/browser/outdoor-wishlist.mjs`。`CLIMBLOG_BROWSER_ENGINE=webkit` でも実行可能。
- 関連：`wishlist-unsaved.mjs`、`outdoor-topo.mjs`、`toyota-grades.mjs`、`record-date.mjs`。
- テストはサンプルデータ・写真のみ。ブラウザー幅やWebKitでの検証はiPhone実機での確認とは区別する。
