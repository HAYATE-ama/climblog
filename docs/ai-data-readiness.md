# 将来のAI用データ蓄積（2026-10-28）

## 現状
本番はSupabaseの本人別user_app_stateにアプリ状態をJSONとして保存する。GitHub Pagesの画面とデータベースは別。ブランチだけで本番DBが分離されるわけではない。旧docs/data-model.jsonは初期の概念モデルも含むため、実保存形式は各モデルと下記の仕様を正とする。

- records：ジム、外岩、トレーニング。既存のID・日付・作成／更新時刻、保存時のジム名・色・グレード・体重を保持。
- 種目：正本のexerciseId、左右、マスターバージョン。表示名を変更しても履歴の名称を勝手に変えない。
- 通常トレーニング：setDetailsの回数／保持秒／外部重量。loadMethodはbodyweight、added、liftFromGround。存在しない重量や体重を推測しない。
- タイマー実績：workoutSessionId、実施時刻、sessionSetResultsの予定・実施量・実施休憩・完了／スキップ。未実施は実施済みとして保存しない。
- 最大出力：握り方・エッジ深さ・保持時間・左右・荷重基準を分離。通常のコースの重量を最大値として扱わない。
- 身体情報・体重履歴、日誌、文章の目標は既存のまま。現在の外部AI向け契約へ身体情報や文章本文を自動追加しない。

## 今回追加した情報

|項目|保存先・意味|
|---|---|
|feedback.rpe|端末内のタイマー途中記録。1〜10またはnull。任意入力|
|feedback.memo|端末内の途中記録。2000文字以内。任意入力|
|rpe / memo|保存時に実施した種目の記録へ反映。既存の記録形式を利用。rpe=0は互換性のための未記録値|
|feedbackScope=session|コース全体に対する感想。同じworkoutSessionIdでは重複して平均へ入れない|
|recordSource|新規手入力manual、タイマー保存timer、前回のコピーcopy。過去にない値は不明として扱う|
|routineExercises.loadMethod|ローカルAI集計を荷重方法ごとに分ける。未記録はnull|
|weightSampleCount / minExternalKg / maxExternalKg|記録されている外部重量のみのサンプル数と範囲。体重を加算した総負荷や1RMではない|
|trainingDataQuality|既知種目・セット詳細・既知の由来の件数、重複除去したRPEのサンプル数、セッション全体と種目別を分けた平均、同一セッション内のRPE矛盾件数|

全体のRPEを同じコースの種目へ複製するのは既存の種目別の保存・閲覧との互換性のため。feedbackScopeとworkoutSessionIdが集計時の境界。個々の種目のRPEと混ぜない。後から一部を編集して矛盾した場合は平均へ入れず件数として検出する。

前回コピーでは元のタイマーセッションID、実測時間、実施セットのメタデータを引き継がない。前回のRPEは未記録へ戻す。種目・予定量・重量・メモは編集用として残す。新しい記録として保存するまで実績は増えない。

## 外部送信
AIコーチ画面は条件の入力を試すだけ。buildCoachRequest等の契約は端末内で呼べるが実APIは接続していない。dataPolicy.externalTransmissionAllowed=false。集計の許可項目にない種目名・自由記述メモ・ユーザーID・実セッションIDを送らない。今回のRPE・品質・重量の集計も数値と正本ID等だけを扱う。将来の送信は別途、明示的な同意と送信範囲の設計が必要。

## 未完了の土台
通常の指トレの握り方とエッジ深さは現在メモで補う。構造化条件が揃うまでは負荷の自動比較／提案を行わない。重量0kgは未設定の初期値と意図した0kgの両方があり、過去の記録から確定できない。記録の由来やRPEも過去へ推測補完しない。

今後は条件の構造化、記録単位の保存への移行、プライバシー確認、サーバー認証・秘密管理・利用量制限・提案検証を順に実装する。先に画面へ項目を増やすより、必要な種目だけに任意項目を置く。
