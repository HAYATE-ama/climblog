# 日々の操作を中心にしたレイアウト

2026-11-20。承認済みの画面サンプルを、既存の記録・タイマー・統計の実装へ適用。

## 主な導線

- スマホは下部、幅1000px以上のPCは左側に「ホーム／カレンダー／トレーニング／統計」を固定。選択中の画面は背景・アイコン・読み上げ用の現在位置で示す。
- ホームは景色、「今日を記録する」、「登りたい課題」「いつものトレーニング」を縦に配置。相談は下部の「記録をまとめて相談する」から開く。
- トレーニングはサーキット、いつものメニュー、目的別コースの順に表示。作成・削除、通常版／短縮版、編集、途中のタイマー復帰は既存の操作を使用。
- 統計は初回に外岩のグラフを表示。外岩／ジム／トレーニングを上のボタンで切り替え、活動全体・最大出力・身体・目標は「その他」から開く。画面移動後も、その起動中の表示対象・期間を維持する。
- カレンダーと選択日の記録はPCでも縦に配置。記録一覧には独立したスクロール領域を確保。
- 記録フォームはスマホで縦並び。既存の中央表示、フォーカス制御、下書き保存、保存操作を維持。
- サーキットは登攀／レストの時間を分けて表示。番号一覧に高さの上限を設け、操作ボタンで課題が隠れない通常の文書順に配置。

## 実装の境界

- `assets/css/modern-layout.css`に共通の色、余白、文字、ナビゲーション、主要画面の外観をまとめる。ライト／ダークに対応。
- 新規の依存や外部サービスは追加しない。ホームの既存GIF、動き軽減、一時停止／再生を維持。
- データ構造、保存先、実績の確定方法、タイマーの時刻計算、統計の集計条件は変更しない。
- ナビからトレーニングを開く際は、既存の`climbLogWorkout.open`を通す。途中の編集やタイマーを初期化しない。
- PWAのキャッシュ世代と静的ファイル一覧を更新。更新確認後に適用し、端末の記録領域を削除しない。

## 検証

- 単体テスト463件。
- ローカルChromeの独立したコンテキストとサンプルデータで、320／390／1280px、ライト／ダーク、ホーム、画面移動、キーボード操作、横はみ出しを確認。
- コース通常版／短縮版、タイマー、一時停止、途中実績、保存、再編集、カレンダーのグループ表示を確認。
- サーキットの登攀／レスト計測、繰り返し完登、途中落ち、取り消し、再読み込み、備考、保存失敗後の再操作、保存・履歴を確認。
- 統計の全6項目、グラフ、期間・条件別表示、記録の閲覧／編集／削除、シーズン設定、空データを確認。
- 記録ダイアログ・設定ドロワーのキーボード、閉じた後の位置・フォーカス復元、下書き、保存を確認。
- PWA更新の取り消し、確認後の更新、端末保存データ保持と旧キャッシュ除去を確認。

実際のユーザー記録はテストに使用していない。iPhone実機でのホーム画面アプリ、ソフトウェアキーボードとバックグラウンドの挙動は未確認。
