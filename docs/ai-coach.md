# AIコーチの土台

状態: **開発中**。このブランチは画面・型契約・端末内集計だけを追加します。外部AI接続、提案生成、AIプラン保存、活動記録への転記はまだ行いません。

## 現在の入口と挙動

- メインメニューの「AIコーチ（開発中）」、ホームの準備画面リンクから開きます。
- 目的・時間（5〜180分）・場所・器具を操作できます。アプリの読み込み直しで初期化します。localStorage、クラウド、バックアップに設定を追加しません。
- 今日を含む28日間の活動を端末内で集計します。件数と日数、通常トレーニングのセット数、最大測定条件数を表示します。未来日・範囲外・ゴミ箱は対象外です。
- 最大出力は種目・握り・厚さ・保持時間・左右・負荷基準を分けます。欠測値を推定しません。これは負荷の適否を判定する機能ではありません。
- 生成ボタンは無効です。サービスを直接呼んでも `COACH_IN_DEVELOPMENT` エラーになります。SDK、fetch、AI秘密キーは含みません。

## 契約 v1

`buildCoachRequest(state, options, referenceDate)` は以下を返します。

- `schemaVersion: 1`
- `options: { purpose, availableMinutes, location, equipment[] }`
- `context`: 期間・件数・セット集計・条件別の測定値・目標/当日コンディションの有無
- `dataPolicy: { scope: 'deviceOnly', externalTransmissionAllowed: false }`

ユーザーID、メール、記録ID、ジム名、メモ、目標本文、身体プロフィール、コンディション本文、削除済み履歴は含めません。ただし数値の履歴も個人に関係する情報です。この契約をそのまま外部送信してよいことを意味しません。

`validateCoachPlan(plan, {availableMinutes})` は、将来の構造化レスポンスの形のみを検査します。

- `schemaVersion`, `title`, `items[]`
- 各項目: `itemId`, `exerciseId`, `phase`, `setDetails[{reps,loadKg,holdSeconds}]`, `restSeconds`, `durationSeconds`
- 既知の種目ID、重複ID、有限数/非負、保持＋セット間休憩の最低時間、利用時間超過を確認
- 未知のプロパティは出力に引き継がない。`completed` や実績の自動作成は行わない

現在の数値上限は画面を壊さないための構造チェックであり、安全なトレーニング処方の保証ではありません。種目カタログも提案済みメニューではありません。

## AI接続前に必要な作業

1. AI事業者・費用・データ利用規約を選び、外部へ送れる項目と利用者の同意を設計する。
2. Supabase Edge Function等でログインを検証し、本人の記録だけを読み込む。APIキーはSecrets管理。ブラウザ/GitHub/config.jsに秘密キーを置かない。
3. クライアントから送られた履歴や「送信可」フラグを信用せず、サーバー側で許可項目を再構築する。
4. 種目ごとの器具要件・負荷急増・体調/指の状態・欠測時の挙動など、処方前後のルールを実装・検証する。サーバーでも契約を検証する。
5. 利用回数制限、通信失敗/タイムアウト/不正レスポンス/無料枠上限への対応を実装する。AI不調時に架空のメニューを表示しない。
6. 提案と実施を分けて保存し、本人が編集・実施確認した項目だけを既存の一括登録へ渡す。プラン用データのクラウド同期・バックアップ・削除も設計する。
7. 開発用環境・アカウントで検証してから本番へ反映する。
