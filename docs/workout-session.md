# セット進行タイマー

## 画面と保存

メニュー選択 → 設定 → 実行 → 結果確認 → カレンダーへ保存。実行画面を新しいメインタブには追加せず、ホーム・日付詳細・既存のお気に入りから開きます。AIコーチは引き続き開発中で、接続や生成を有効化しません。

種目を順番に実施する形式です。種目間を繰り返すサーキット形式は含みません。メニュー例は処方ではなく、編集して使う初期値です。

- `workout-model.mjs`: 設定検証、運動/休憩の状態遷移、実績、復元、保存用パッチ
- `workout-screen.mjs`: 設定/実行/結果画面とアカウント別の端末内チェックポイント
- `screen-awake.mjs`: 単独休憩と実行タイマーが共有するScreen Wake Lock管理
- `app.js`: 一括保存と日付/実行回ごとの表示。`climbLogSessionApi.commit`は再保存を検知
- `workoutReceipts`: クラウド/JSONバックアップ対象の保存済み実行ID。削除した活動を古い途中データから再作成しないために保持

開始時にメニューの独立コピーを作るため、その後にお気に入りを変更しても実行中の内容は変わりません。保存前の修正は実績だけを変更し、元のメニューには反映しません。記録日・体重は実行対象日で固定し、0時を過ぎても選択中の別日に保存されることはありません。

時間式を途中で「ここでセット完了」にした場合は実測した秒数を初期実績にします。回数式は目標回数を初期値とし、本人が結果確認で修正します。未完了のセットを含めて保存したい場合は、先にセット完了を押して実績を確認してください。

所要時間は、時間式では設定時間＋休憩。回数式を含む場合は既知の秒数と「回数種目の実施時間」を分けて表示します。統計のdurationMinutesは完了したセットの実測運動＋その後の休憩を集計します。後日の記録編集ではsetDetailsが集計の正本で、sessionSetResultsは保存時のスナップショットです。

## 画面の消灯抑制

HTTPS/localhostで `navigator.wakeLock.request('screen')` を使用します。実行中と休憩中に取得し、一時停止・結果確認・画面を離れた時に解除します。回数式も実行中扱いです。表示が戻った後の再開操作で再取得します。複数タイマーの所有状態を共有し、停止済みのタイマーが別の実行中タイマーのロックを解除しないようにします。

OS側の省電力制限、未対応ブラウザ、本人の手動ロックを強制的に防ぐことはできません。取得/解除/拒否を表示し、必要なら再試行できます。画面を離れた間は進行を一時停止し、バックグラウンドで完了したことにはしません。

参考: [MDN Screen Wake Lock](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)。APIキー・外部ライブラリ・課金サービスは追加しません。

## 開始前カウントダウン

新規メニューには5秒の準備時間を設定します。設定画面で「なし・3秒・5秒・10秒」を選択でき、お気に入りにも保存します。最初の種目の前に一度だけ表示し、セット間の休憩へ重ねて準備時間を追加しません。

準備画面は残り秒数と最初の種目を表示し、一時停止・再開・「今すぐ開始」に対応します。準備中も消灯抑制を維持します。アプリを離れた場合は他の段階と同様に一時停止します。

準備は運動・休憩・完了セットとして記録しません。準備中に中止しても実施記録を作らず、集計のdurationMinutesにも加算しません。旧途中記録でpreparationSecondsが省略されている場合は準備フェーズを追加せず、既存の進行位置を保持します。旧お気に入りから新たに開始する場合は5秒を初期値にします。

追加7ケースと、PC/スマホ幅での準備画面・一時停止・自動開始を検証しています。消灯抑制の実機制約は前述のとおりです。

## 状態表示とタイマー音
運動中は赤系、休憩中は緑系、停止中は中立色。残り3・2・1秒と開始・休憩・完了を音で通知し、実行中にオン/オフできます。詳細と端末制約は [タイマー通知](timer-cues.md) を参照してください。
