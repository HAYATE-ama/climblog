# 外岩シーズンの段数

統計 → 外岩 → 「シーズンを設定」で、任意の名前と開始日・終了日を保存する。開始・終了日を含め、年をまたぐ期間も集計する。入力は端末のカレンダー、保存した期間の表示は YYYY/MM/DD。従来の年別表示も選択できる。

## 集計

- 新規完登の段数合計を大きく表示し、新規＋再登の合計を「再登込み」として括弧で併記する。例：新規10段＋再登4段なら「新規10段（再登込み14段）」。
- 新規は同じ課題につき期間内に1回。再登は同じ課題・同じ日につき1回。別日の再登はそれぞれ加算する。
- 同日・同課題の重複記録は、新規と再登をまたいでも加算しない。記録自体は削除しない。
- 初段は1、二段は2など、ボルダーの日本段級グレードの段だけを合計する。級、他のグレード体系、曖昧なグレードは換算しない。
- 課題の識別には岩場・エリア・課題名・種別を使う。表記やエリアの違いは別課題として扱うため、誤記は記録から修正する。

## 過去の記録

2026-11-11のユーザー指定により、更新後のログインで既存の外岩完登記録を一度だけ新規に揃える。明示的に再登と保存されていた既存記録も対象。敗退の結果、日付、グレード、トライ数、メモは変更しない。移行済みの印 preferences.outdoorAscentResetVersion=1 を記録と一括保存し、その後に選んだ再登を再ログインでリセットしない。

外岩の完登区分は「新規完登」「再登」の2択。初期値は新規完登とし、履歴から再登を推測しない。旧下書きの自動判定も新規へ置き換える。岩場・課題名がなければ同一課題の重複排除はできない。

## 保存と検証

シーズン設定は既存の preferences.outdoorSeason、明示した区分は各記録の ascentType に保存する。既存の同期・バックアップを使用する。旧記録と旧バックアップに新しい項目は必須としない。移行は通常の端末保存・保留データ・クラウドの版照合を使用する。未同期データとクラウドに競合がある場合は先に既存の確認画面を出し、勝手に上書きしない。容量不足時は移行済みの印も記録も部分的に保存しない。旧バックアップを復元し移行済みの印がない場合は、次のログインで同じ移行を適用する。AI処理とDB定義は変更しない。

単体テスト：tests/outdoor-season.test.mjs。画面テスト：tests/browser/outdoor-season.mjs（本番通信を遮断したサンプルで設定、編集、再表示、スマホ幅とPC幅、両テーマを検証）。実機のネイティブ日付選択UIは別途確認が必要。

移行テスト：tests/browser/outdoor-ascent-migration.mjs（サンプルの旧記録、既存再登、一時的な同期失敗、再ログイン後の再登維持、旧下書き、容量不足、既存の同期競合）。
