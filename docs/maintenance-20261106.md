# 継続メンテナンス 2026-11-06

対象は現行ClimbLogのみ。開始時刻は日本時間0:32、依頼上限は同日6:00。主担当が画面・記録導線、サポート1名が保存・履歴を調査し、競合しないファイル単位で実装・レビューした。

## 根拠を確認して採用した改善

|問題|改善|確認|
|---|---|---|
|前回コピー・測定プリセットで保持方法が瞬間挙上へ戻る|測定方法をコピーし、旧条件は未設定として扱う。下書き復元順も修正|3秒保持のコピー→プリセット→閉じる→復元→保存、元記録不変|
|保存通知が2つ重なりスマホ画面を覆う|保存の案内を一つに集約。キャラクターの反応は維持|両テーマ、320/390/1280px。390pxの実表示も目視|
|保持方法が一覧・詳細で分かりにくい|瞬間挙上・保持秒数・旧未設定を表示|モデルと閲覧画面|
|容量不足で未同期snapshotだけが保存できず、保存成功と扱われる|account複数キーと未同期snapshotを同じ保存単位にし、失敗は元へ戻す。未保存を明示|モック容量不足、入力保持、reload、再試行、logout|
|同一accountの別タブから新しい記録を上書きできる|保存前に最後に読込んだpayloadと現在のpayloadを比較し、古い画面からの保存を拒否|2タブmockでB追加→A拒否→下書き復元→再読込後保存|
|身体情報の2つの保存が途中で失敗すると一部だけ変更される|プロフィールと当日の体重を一括保存|モック失敗で両方不変、入力維持|
|設定の保存失敗が分からない|身体・目標・ジム・表示設定・削除で失敗を表示。表示設定は保存失敗時に選択を戻す|保存失敗モック、正常な設定操作|
|過去の未記録体重が後日の履歴値で補完される|編集では記録時snapshotと未記録を保持。新規だけ当日の履歴を参照|既存63kg/未記録と現在55kgを分けて検証|
|種目・通常/最大測定・活動タイプの変更後に古い専用値が残る|編集した記録だけ種目IDと専用値を整合。元内容は編集履歴に保持|モデル＋実際のフォーム操作。メモ/RPEだけでは実績を変えない|
|タイマーの実績60秒→20秒の変更が集計時間に反映されない|時間式は実績と動作時間を一致。休憩と回数式の経過は保持|20/90/0秒、回数式のモデル検証|
|カレンダーが42日それぞれ全履歴を検索する|日付別の索引を一度だけ作成。日付の読み上げに記録件数を追加|2万件で件数・順序・種別・元データの不変、既存カレンダー操作|
|更新確認で準備中/通信中が分からず連打できる|状態とbusyを表示し、処理中は重複確認を防止、失敗後は再試行可能|遅延/失敗モックと実際のService Worker更新|
|相談レポートの安定ID・ジム敗退・不明重量の区別が一部欠ける|必要な記録項目をallowlistへ追加。活動タイプに無関係な古い項目は出力しない|ローカル生成、共有初期オフ、コピー/保存、外部API呼出なし|

短い通常トレーニングは1〜4分も選択可能にした。統計にはタイマーの分数が休憩を含むことを明記した。編集履歴の時刻を端末の現地時刻にし、操作名を日本語にした。READMEの旧API案内を現在の相談用レポート運用へ更新した。

## 検証と限界

実データ・本番アカウント・実AI APIは使用していない。画面はローカルChromiumと専用サンプル、認証/同期はローカルmock。iPhone実機の音声・バックグラウンド制限、実Supabase障害は未確認。

localStorageの複数キー保存は失敗時のrollbackを行うが、OS/ストレージ自体の故障への完全な耐久性を保証しない。2タブ保護は古い画面からの逐次上書きを防ぐもので、プロセス間の厳密な同時排他ではない。過去に既に失われた記録の復元機能ではない。

データの自動削除、DB移行、新たな外部送信、課金、認証方式の変更、依存追加は行っていない。ユーザーのAGENTS.mdと.vscodeの変更は公開対象から除外する。
