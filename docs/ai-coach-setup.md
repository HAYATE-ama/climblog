# Gemini無料枠でAIコーチを試す

確認日：2026年10月28日（日本時間）。本番の記録・DB・秘密設定は今回の開発で操作していません。キーなしでも記録・いつものメニュー・タイマーは使えます。実際のAPI呼び出しは、以下の初期配置と本人によるキー登録・有効化の後です。

## 調査結果と採用モデル

標準モデルは安定版 `gemini-3.5-flash-lite`。2026-10-28にGoogleの料金表でStandardのテキスト入出力が無料枠対象であることと、モデル資料で構造化出力への対応を確認しました。新規プロジェクトではこのモデルを使用してください。

以前案内した2.5系は、現在Google側で過去に利用実績があるユーザー向けに制限されています。料金表に無料枠があっても、新規キーで利用できるとは限りません。旧 `gemini-2.5-flash-lite` / `gemini-2.5-flash` は、すでに利用権限のあるプロジェクトの明示的な設定としてのみ残します。モデルを自動で切り替える処理はありません。3.5系はthinkingLevel=MINIMALを使い、2.5系のthinkingBudget・temperature・candidateCountを送りません。無料から有料への切り替え、検索・Grounding・ファイル・ツールの追加はしません。

GoogleのRPM・TPM・RPDはプロジェクト単位で、実際の制限はAI Studioで確認する仕様です。一般値を固定して保証しません。GoogleのRPDは米国太平洋時間の午前0時にリセットされます。アプリの同日再利用・日次上限は日本時間であり別の仕組みです。同じGoogleプロジェクトを他アプリでも使う場合、その消費も合算されます。

## 無料枠のデータ条件

日本からの無料サービス利用では入力・生成結果がGoogleの製品改善に使われ、人による確認の対象になる場合があります。規約は個人情報・機密情報・センシティブ情報を送らないよう求めています。18歳以上での利用などの条件も本人が確認してください。

そのため、この無料運用は**個人の履歴・身体情報・体調の回答・登録済み目標・保存済み記録のメモ・メール・識別子・日付・場所をGoogleへ送信しません**。履歴・身体・体調・目標の共有設定はすべてオフ固定です。送るのは定型選択の目的、利用時間、器具、登る種目、登録済みの候補種目、構成の参考ルールと、任意の備考（最大500文字）です。備考は今回の仕様として無料運用でも送信します。氏名・連絡先・詳しい症状などを書かないでください。個人の記録を参照して送信する機能は無料運用では利用できません。この制限は同意チェックで解除できません。将来、個人履歴を外部AIへ送る場合は、データ条件に合う別の運用と再同意を設計する必要があります。

痛み・強い疲労で生成を止める判断と、状態不明なら軽い候補に絞る判断はアプリ内で行います。最大出力・高負荷指トレ・自動増量の提案はしません。旧バージョンの同意は無効となり、現在の運用モード向けに同意し直すまでAIはオフです。既存記録・保存済みメニュー・過去のAI実施記録は消しません。古いOpenAI提案をGeminiの今日の提案として表示しません。

## 無料運用と将来の有料運用

サーバー設定 `AI_USAGE_MODE` は省略時 `free` です。画面や端末から変更できません。今回は無料のまま運用し、有料への自動変更は行いません。

将来は本人が有料APIの課金状態とデータ条件を確認した後、サーバーで `AI_USAGE_MODE=paid`、`AI_PAID_DATA_CONFIRMED=true` を設定して関数を再配置します。これは実際のGoogleプロジェクトの課金切り替え操作ではありません。無料キーのままpaidと申告して個人データを送る運用は行わないでください。Google側のTierはキーから自動判定できません。

有料運用では、改めて同意した後、過去28日の数値集計、身体情報、選択した痛み・疲労、目標文章（先頭200文字）を個別に共有できます。初期値はすべてオフです。記録のメモ・メール・その他の自由記述は送信しません。無料運用に戻ると共有は強制オフになり、有効な同意を引き継ぎません。モード変更をサーバーで検知すると旧同意を保存状態でも無効化します。

有料運用でも現行の回数上限は保守的に据え置きます。上限やモード設定はGoogleのドル単位の請求上限を保証しません。

## 1. Google AI Studioでキーを取得

1. [AI StudioのAPIキー画面](https://aistudio.google.com/apikey)を開きます。
2. 無料枠で試すプロジェクトを選択または作成します。課金アカウントの紐付けや有料へのアップグレードは行いません。
3. キーを作成し、本人が安全に保管します。チャット・GitHub・config.jsには貼らないでください。
4. AI StudioでそのプロジェクトのTierがFreeであることと、対象モデルの実際のレート制限を確認します。必要に応じてキーをGemini APIだけに制限します。ブラウザーのリファラー制限はサーバー経由の通信に適しません。

アプリはキーから課金Tierを判定できません。有料プロジェクトのキーを入れるとモデル自体が無料枠対応でも課金される可能性があります。無料枠を確認したというサーバー設定は本人の確認を記録するもので、Google側の課金停止機能ではありません。

## 2. SupabaseのSQLを配置

Supabase SQL Editorで、リポジトリの以下のファイルを順に実行します。

1. `supabase/migrations/202610280001_ai_coach.sql`：初期テーブル、本人限定RLS、生成予約と完了処理。すでに配置済みならこの段階は省略できます。
2. `supabase/migrations/202610280002_gemini_free.sql`：旧同意での生成をオフにし、予約処理へ全体1分間隔の制限と同意別キャッシュ判定を追加。既存のクライミング記録は変更しません。

3. `supabase/migrations/202610280003_coach_usage.sql`：分単位の間隔を受け取る新しい予約関数を追加し、今回の再同意に備えて旧同意を無効化します。001・002まで配置済みなら003だけを追加します。既存の記録を変更しません。

ブラウザーから3つのAI用テーブルへの書き込みはできません。認証済み本人は自分の行だけ閲覧できます。生成予約はservice_role限定の関数がトランザクションのロックを使い処理します。

## 3. Supabase Secretsを設定

Authentication → Usersで自分のUID（メールではなくUUID）を確認し、Edge Functions → Secretsへ本人が次の値を登録します。

| 名前 | 設定値 |
|---|---|
| AI_USAGE_MODE | 現在は `free`（省略時もfree）。将来のみ明示的にpaid |
| AI_PAID_DATA_CONFIRMED | 現在は未設定。将来、有料APIの条件・課金状態を確認した場合だけtrue |
| AI_MIN_INTERVAL_MINUTES | 生成の最小間隔。1〜60分、既定1分。全ユーザー合計で適用 |
| GEMINI_API_KEY | AI Studioで作成した無料プロジェクトのキー |
| AI_ALLOWED_USER_IDS | 自分のユーザーUID。複数ならカンマ区切り |
| AI_FREE_TIER_CONFIRMED | Free Tierと無料対象モデルを本人が確認したら `true`。未確認なら未設定 |
| GEMINI_MODEL | 新規は `gemini-3.5-flash-lite`。既定も同じ。旧2.5系の設定は自動置換されないので変更が必要 |
| AI_DAILY_LIMIT | 任意。1ユーザー1日1〜2回。既定2回 |
| AI_MONTHLY_LIMIT | 任意。1ユーザー月1〜30回。既定30回 |
| AI_GLOBAL_MONTHLY_LIMIT | 任意。サーバー全体月1〜30回。既定30回 |
| AI_ALLOWED_ORIGINS | 開発時のみ任意。localhostの完全なoriginをカンマ区切り。本番originは許可済み |

キー・許可UID・現在のモードの確認設定・許可モデルが揃わなければ接続準備中のままです。0や範囲外の上限値は既定値に戻るため、停止は画面のAIオフ、または現在のモードに対応する確認設定（freeでは `AI_FREE_TIER_CONFIRMED`、paidでは `AI_PAID_DATA_CONFIRMED`）を `false` にしてください。`OPENAI_API_KEY` と `OPENAI_MODEL` は今回のエントリーポイントでは使用しません。

Supabase組み込みのSUPABASE_URL / SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEYをサーバー内部だけで使います。秘密保管フォルダをエージェントに読ませる必要はありません。

## 4. Edge Functionを配置

Supabase CLIを用意し、現在のClimbLogリポジトリ直下で実行します。PROJECT_REFは本人のプロジェクトIDに置き換えてください。

```powershell
npx supabase login
npx supabase functions deploy ai-coach --project-ref PROJECT_REF
```

index.tsだけの貼り付けではなく、共有種目定義を含むリポジトリから配置してください。JWT検証は `supabase/config.toml` で有効です。関数内でも本人確認と許可UIDの検証を行います。PagesへのpushだけではSupabaseのSQL・関数・Secretsは反映されません。変更後は関数も再配置してください。

## 5. アプリで有効化・確認

ログイン後、初回のみAI利用確認のポップアップが表示されます。説明を読み「同意して利用する」または「今は利用しない」を選択します。本人のai_coach_settingsへモードと同意バージョンを保存するため、再ログイン・別端末で繰り返し確認しません。閉じるだけの場合や保存失敗の場合は未確認のままです。通信できない場合も通常機能は使用でき、後から歯車 → AIコーチの利用で確認・変更できます。無料／有料など送信条件が変わると再確認します。今回の備考送信追加では同意バージョンを更新しています。

AIコーチで目的・登る種目 → 時間・場所・器具 → 状態 → 備考 → 送信内容を順に確認し、最後の「AIにコースを作成してもらう」を押します。画面を開いた際の自動生成はありません。入力途中の下書きはアカウント別に端末へ保持し、送信ボタンでSupabaseに条件を保存した後、AIへ要求します。

生成間隔の待機中はボタン自体が「あとN秒で生成できます」と1秒ごとに更新されます。日次上限の場合は「本日の利用上限に達しました」と表示します。待機終了後に自動送信しません。

新しい画面に古い関数を組み合わせた場合は「AI用サーバーの更新が必要です」と表示し、送信を止めます。最新版の関数を再配置してください。今回の変更に追加SQLはありません（初期001〜003は必要です）。

提案 → このコースを確認・開始 → 必要に応じて種目・セットを編集 → 開始 → 完了後カレンダーへ保存、の順です。生成や開始だけでは実施記録は増えません。保存済みメニューとして残す既存操作も使えます。

同日の提案は端末を跨いで再利用します。再生成は確認を求め、回数枠を追加消費します。失敗・中断も試行回数に含めます。自動再試行はしません。2分以上中断した予約は次の生成要求時に失敗扱いになります。Googleから429等が返ったら通常のメニューを使い、AI Studioで枠を確認してください。

生成の間隔は全ユーザー合計で `AI_MIN_INTERVAL_MINUTES` 分以上（既定1分）、出力最大4000トークン、入力最大30000文字です。画面には今日の残り回数と、待ち時間中の次回利用時刻（日本時間）・残り秒数を表示し、生成ボタンを無効化します。待ち時間が終わっても自動送信せず、ボタンを再び押せる状態にするだけです。制限の実判定はSQLで行うため、別端末や再読み込みでも回避できません。同日分の保存済み提案の取得・閲覧・開始は回数と待ち時間の制限を消費しません。この上限だけでGoogleの無料枠や料金ゼロを保証することはできません。実際のプロジェクトの枠がさらに小さければエラーで停止します。

## 保存と検証範囲

元の提案、入力ハッシュ、設定、モデル、取得できた使用量、採用した編集済みプランをSupabaseへ保存します。取得できない使用量はNULLです。採用履歴の通信失敗はアカウント別の端末キューに保留し、再送します。実施記録にも提案IDと編集有無を保持します。AIをオフにしても保存済み記録は削除しません。

実APIキーを使わず、正常応答、キーなし、認証エラー、429、通信中断、不正JSON、拒否、上限、再同意、個人データの未参照、同日再利用、編集・開始・実施保存を検証します。画面はPC・スマホ相当のChrome、ライト／ダークで確認します。実際のGoogle無料枠、Supabase上でのSQL実行・Denoの配置とバンドル、iPhone実機は未確認です。初回配置後、本人のテストアカウントで確認が必要です。

## 生成失敗の診断

状態を確認しても直前の失敗理由を表示します。旧 `GENERATION_FAILED` は原因を後から復元できません。新しい関数では送信形式（PROVIDER_BAD_REQUEST）、モデル不在（PROVIDER_NOT_FOUND）、通信・時間切れ、回答JSON、種目・左右・運動量・予定時間・利用時間の検証、結果保存を区別します。キー・入力・Googleのエラー本文・回答本文は診断表示やログへ出しません。分類の追加でGoogleへの自動再試行や上限解除は行いません。コード更新後はgit pullとai-coachの再配置が必要です。SQL・Secretsの再入力は不要です。

`PROVIDER_NOT_FOUND` が2.5系で発生する場合は、上の利用制限が原因候補です。Supabase SecretsのGEMINI_MODELをgemini-3.5-flash-liteに変更し、最新版を取得して関数を再配置します。SQL・キーの再発行は不要です。過去の失敗は回数に残し、上限到達後は日本時間の翌日まで待ちます。旧エラー表示は次回の成功まで残ることがあります。実キーでの利用可否・実応答は本人のプロジェクトで確認してください。

## 状態確認と生成失敗への対応（2026-10-29）

「状態を確認」はSupabaseの設定・利用状況を読み取り、Googleの生成APIを呼びません。ボタン直下に処理中表示と確認完了時刻（日本時間）を表示し、前回の生成エラーとは区別します。15秒で完了しない場合は時間切れを表示し、自動再試行しません。遅れて届いた結果で画面を上書きしません。

再生成の確認は画面内のダイアログです。「確認して生成する」を押した場合だけ送信し、取消・Escape・認証解除では生成しません。確認後も回数上限・日付・アカウントを再検証します。

サーバーではPostgRESTの正常な空応答（200/201/204）を保存成功として扱います。以前は空本文のJSON解析で、設定保存後にもSETUP_REQUIREDとなり、Googleを呼ぶ前に止まる場合がありました。

AIのdurationSecondsがセット内容から計算した最低予定時間より短い場合、その予定メタデータだけを引き上げます。回数・セット数・休憩・重量は変更しません。補正後も利用時間、種目、左右、運動量、重量の検証をすべて適用し、上限超過を切り詰めて採用することはありません。保存済み・ユーザー編集済みコースの厳格な検証も維持します。

この対応にSQLの追加実行・キー再登録・利用上限の解除は不要です。実生成の試験ではGoogleからの応答とDRAFT_TIMEを1回確認しました。修正後の最終生成はブラウザー操作の応答停止により送信・成功を確認できていないため、成功済みとは扱っていません。重複送信を避け、状態確認で履歴を確認してから判断します。自動的に生成を再送しません。
