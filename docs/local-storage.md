# 端末保存（2026-11-19）

ユーザーの指定により、単一端末での個人利用を基本とし、ログイン・クラウド同期を廃止した。アプリの入口 `cloud.js` は旧インストールとの互換のため名前だけ残した `local.js` の読み込み口。Supabase SDK・認証・API・同期リクエストは起動しない。旧サーバー・DB・RLSの削除や変更は行っていない。

## 保存と移行

- `accountKeys` の既存キーとデータ形式を継続する。通常の記録・設定・身体情報・履歴・ゴミ箱・メニューは端末に保存する。
- 初回は公開設定に対応する旧 `owner` メタデータを参照する。トークン・パスワードは読まない。
- 同じ保存先の有効な未同期スナップショットを最後のローカル編集として引き継ぐ。削除済み記録を復活させないため、古いキャッシュとの無条件の結合はしない。未同期データに含まれない項目は端末の値を維持する。
- 移行前の各キーの生文字列と対象の未同期内容を `climbLogLocalMigrationRecovery` に保管し、元の未同期キーも残す。これは同じ端末内の復旧用であり、紛失対策ではない。
- `climbLogLocalProfile` を最後に保存する。移行済みなら旧スナップショットを再適用しない。途中で保存に失敗したら書き込みを巻き戻す。
- 旧保存先IDを端末内の識別に維持し、サーキット・コース・休憩タイマー・入力下書きを引き継ぐ。サインアウト・自動消去は行わない。
- 別アカウントの未同期内容は混ぜない。保存先が不明なら元データを保持して説明を表示する。複数の保存先から特定できなければ、自動移行を止める。
- 通常保存は既存の一括パッチ方式を利用する。容量不足では元の値を復元し、未保存と表示する。別画面の更新を検出した場合は再読み込みを案内して上書きを止める。

クラウドだけに存在する記録は、この移行で取得できない。必要なら既存のJSON書き出しを「設定 → データ管理 → 復元」から取り込む。サイトデータ削除や再インストールを復旧手順にしない。ブラウザーとホーム画面アプリ、端末間で保存領域が共有されるとは保証しない。

## オフラインと更新

課題の写真はIndexedDB、写真との紐付けとマークは通常のローカル保存領域に置く。任意のJSONバックアップには画像も含める。画像の大きさや保存・復元の扱いは [写真・トポ](outdoor-topo.md) を参照。

初回はオンラインで画面資源を保存する。Service Workerは版ごとの画面資源を先にキャッシュし、未訪問の画面もオフラインで開けるようにする。公開更新は従来どおり確認後に切り替える。新しい静的資源を追加した場合は `assets/js/offline-assets.js` の一覧とキャッシュ世代を更新する。記録はService Workerのキャッシュには保存しない。

`navigator.storage.persist()` を利用可能な環境で要求するが、永続保存の承認や端末紛失からの復旧は保証しない。通常操作にバックアップは不要。機種変更時には任意のJSON書き出し・復元を使う。

## 検証

- `tests/local-storage.test.mjs`：未同期編集・削除・旧下書きの保存先、移行の再実行、破損データ、容量不足、他の保存先との分離、別画面の更新。
- `tests/browser/local-only.mjs`：実際の起動処理をサンプルで検証。ログイン・外部リクエストなし、旧途中記録の再開、端末保存、オフライン再起動、容量不足、複数画面、両テーマとスマホ幅。
- サーキットの旧下書きv1はv2へ変換し、完登チェックを1回として保持する。新しい回数は保存・再読込・取り消し・JSON復元で保持する。

実ユーザーのクラウドデータやブラウザープロファイルはテストに利用していない。iPhone実機・各端末の既存記録の実移行は未確認。
