# 気象庁の予報連携

歯車 → 外岩の候補日で岩場・都道府県・予報地域・曜日・時間を保存する。旧設定には予報地域がないため、再選択が必要。岩場名による自動推測はしない。

カレンダーの「すべて」「外岩」で天気情報を表示。指定曜日、活動時間未終了、当日の降水確率30%以下、週間信頼度C以外に加え、前日の雨条件を満たす日を「○ 候補」、それ以外の確率既知の指定曜日を「△ 要確認」とする。過去の日・予報のない日・未発表の降水確率は判定しない。数値は6時間区分で活動時間を全てカバーできる場合その最大値、なければ週間の日全体の確率を用い、詳細に区別を表示する。30%はアプリの固定条件で気象庁の推奨値ではない。当日の候補には、選んだアメダス地点の前日00:00〜24:00の実降水量が設定値以下（初期1mm、選択肢0/1/3/5mm）であることを要求する。今日00:00の24時間降水量（品質フラグ0のみ）を用いる。地点未選択・欠測・地点や日付の不一致を0mmとして扱わない。0mmも観測分解能未満の雨を否定する値ではない。先の日付では前日の雨・雪・雷の予報がなく、1日全体の降水確率30%以下・信頼度C以外を要求する。未来の前日雨量をmmとして捏造せず、予報であることを詳細に表示する。雨の観測地点は利用者が岩場に近い地点を選ぶ。気温・風・岩の乾燥・警報の判定は含まない。安全や登攀可否を保証する情報ではない。

## データと取得
- 元データ：https://www.jma.go.jp/bosai/common/const/area.json
- 天気コード日本語名：https://www.jma.go.jp/bosai/forecast/ （TELOPSの名称を抽出）
- 降水観測地点表：https://www.jma.go.jp/bosai/amedas/const/amedastable.json （elemsの降水観測フラグがある地点だけを収録、JMA観測地域番号を都道府県に対応付け）
- 前日観測：https://www.jma.go.jp/bosai/amedas/data/point/{stationCode}/{todayYYYYMMDD}_00.json （日本時間）
- 観測解説：https://www.jma.go.jp/jma/kishou/know/amedas/kaisetsu.html
- 予報：https://www.jma.go.jp/bosai/forecast/data/forecast/{officeCode}.json
- 地域・コード表抽出日：2026-10-27。出典：気象庁ホームページを加工。利用条件：https://www.jma.go.jp/jma/kishou/info/coment.html
- 週間予報：https://www.jma.go.jp/jma/kishou/know/kurashi/shukan.html

ブラウザーから公式サイトへ直接GET（CORS *を確認）。AI/MCP/APIキー/追加バックエンドは不要。予報地域の公開コードだけをURLに使い、岩場名・記録・身体情報・認証情報は送らない。credentials omit、referrerなし。接続先には通常の通信情報（IP等）が伝わる。外部送信は利用者の天気連携指示に基づく。サービスワーカーとクラウドの保存対象にはしない。

端末メモリに30分キャッシュし同時取得をまとめる。非表示では自動取得しない。10秒タイムアウト。18時間を超える発表・未来の発表・不正な応答は使用しない。通信失敗時に過去の候補を残さない。表示中は約1分後またはオンライン復帰時に再確認する。予報地域変更・認証ロック時の遅い応答は破棄。週間の地域は一致するコード、確認済みの合併区域、官署内で単一の週間区域のみ採用し、複数の別区域から推測しない。温度観測所を無理に対応付けしないため気温は今回表示しない。

気象庁ホームページ用JSONは安定した公開APIの契約ではない。URL・形式・CORSの変更時は予報が利用できなくなる可能性がある。画面の気象庁リンクで原本を確認できる。取得元の全地域に対するライブ試験は行わず、複数地域の実応答と構造テストで検証する。

テスト：weather.test.mjs（地域、時間帯、欠損、信頼度、鮮度、取得・キャッシュ）、browser/outdoor-weather.mjs（隔離した仮予報で幅320/390/1280、両テーマ、表示切替、失敗、ロック、記録非変更）。実機iPhone未確認。

## スマホ・ホーム画面アプリの更新

更新通知が従来はデータ管理画面にしかなく気付きにくかった。新しいサービスワーカーの待機を通常画面でも案内する。初回インストールを更新と誤認しない。入力を保存してからユーザー操作で切り替え、自動再読み込みは行わない。データ管理に「最新版を確認」を追加。画面復帰時にも30分間隔で更新を確認する。registerのupdateViaCacheはnone、静的資源の取得はcache:no-cacheでHTTPキャッシュを再検証し、PWAキャッシュの世代も更新。対象はClimbLogのスコープのみで、localStorageや記録は消さない。

カレンダーに「天気を再取得」「場所・条件を変更」を追加。予報地域不足は設定の該当項目を直接開く。地域/観測地点/日本日付変更で取得状態を分離する。スマホ上の症状そのものはiPhone実機にアクセスできておらず断定していない。ブラウザーのWebKit実行環境も未導入。Chromeの320/390/1280幅で表示と実際のService Worker旧版→新版遷移、更新キャンセル、保存データ保持を検証。

旧版のホーム画面アプリには新しい更新案内がまだないことがある。保存後に設定 → データ管理の既存の「新しいバージョンがあります：更新」を使うか、一度アプリを閉じて開き直して確認する。ホーム画面アプリの削除・サイトデータの消去は必要ない。更新後、外岩設定で雨の観測地点を選択する。
