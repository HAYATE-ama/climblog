# 閲覧画面の整理と種目追加

## 変更内容

- カレンダーの記録カードの本文/Enter/Space、ホームの足跡から `recordViewer` を開きます。保存済みの値を表示するだけで、入力途中の下書きを作りません。
- 「編集」で既存の記録編集を開きます。編集にはセット別入力を残し、過去の重量/体重スナップショットやグレードの扱いは変更しません。
- 削除は既存の確認＋ゴミ箱を共通APIで呼び出します。
- 「この内容でもう一度」は通常トレーニングに表示します。同じworkoutSessionIdの有効な種目を一緒に呼び出し、現在の実績を新規設定へコピーします。記録日/ID/過去の体重は引き継がず、保存済みの記録を変更しません。休憩は初期値、開始前確認が必要です。最大出力・ジム・外岩にはこのボタンを表示しません。
- 閲覧にタイマー・フォーム・お気に入りは表示しません。編集/後からの記録のフォームからも休憩タイマーとお気に入り管理を除きます。詳細なセット入力と測定プリセットは編集時に必要なため残します。
- 単独休憩タイマー、お気に入りの呼び出し/上書き/削除、「実施済みトレーニングを入力」は専用の実行画面にまとめます。メニュー削除で過去の記録を削除しません。

## 種目

`exercise-catalog.mjs` に一元化し、通常トレーニング・ウォームアップ・ゴムバンドのoptgroupで表示します。実行設定と後から入力の両方が使用します。index.htmlの初期選択肢もカタログに合わせてあり、一致をテストします。古い固有の種目名は「保存済みの種目」として残すため、閲覧/編集で失われません。

追加した名前は選択肢です。回数・重量・運動法の指導や処方を生成する機能は含みません。AIコーチは開発中のままです。

## 実装

- `record-viewer.mjs`: 読み取り専用描画・セット一覧・再実行対象・dialog/明示操作
- `exercise-catalog.mjs`: 種目カテゴリと安全な選択肢描画
- `app.js`: recordApi.view/remove、閲覧と編集の分岐
- `workout-screen.mjs`: 再実行コピー、メニュー管理、後から記録する入口

新しい保存コレクションやSQL移行は不要です。閲覧は既存のsetDetailsを正本とし、古いまとめ入力では回数/セット数/重量を展開して表示します。保存されていない保持秒数は推定しません。
