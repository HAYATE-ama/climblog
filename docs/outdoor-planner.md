# 外岩候補日：複数岩場と天気AI

確認日：2026-10-31。対象は現行ClimbLogのみ。実AI呼び出し・課金設定の変更・個人記録のテスト変更は行わない。

## 操作

歯車 → 外岩の候補日 → 「複数の岩場・比較の条件」で詳しい候補日判定を有効にする。
現在の岩場を入力し、「別の岩場を追加」で次の岩場を追加、最後に「設定を保存」。
未保存の岩場の変更は切り替え時にフォーム内の下書きとして保持する。保存前に画面を離れる場合は従来の破棄確認を行う。
所在地が不明な岩場は都道府県・予報地域を空欄で保存可能。岩場名から地域を推測しない。
既存の単一岩場設定は、有効化しない限り従来の判定・設定値を維持する。

変更前：単一岩場 → ○候補 / △要確認。
変更後：岩場選択 → 既存カレンダー → 日付を選んで理由・不足情報。
AI比較は折りたたみ内で手動実行。結果の最初の3件を表示し、残りは折りたたむ。

## 判定と限界

- 最大10岩場。土日祝の日中／平日ナイト／両方の区分、行ける曜日と同日内の活動時間、地域・観測地点、特徴、見送り設定を岩場別に保存。
- 直近3日を中心に、今日を含む7日間を表示。4日目以降は参考。登れる時間帯の自動探索・日没時刻の計算は未実装で、指定した時間帯を使う。
- 前日の雨量は優先条件。詳しい判定を有効化するとフォームの初期目安は3mm。超過を一律除外せず「条件付き」にする。0/1/3/5mmの岩場別選択を維持。
- 降水確率30%超、信頼度C、前日雨の優先条件不一致は条件付き。30%はアプリの比較目安で気象庁推奨値ではない。
- 雷・雪が地域予報にある場合、または利用者が閉鎖・増水等で見送り設定をした場合は「× 見送り」。当日の地域予報全体を使う保守的な判定で、時間帯を分けて雷雨がないとは断定しない。
- 降水確率・前日雨・乾燥時間等が不足すれば「? 判断材料不足」。リスクが分かる日は「△ 条件付き」と不足情報を併記。
- 「○ おすすめ」は必要情報がそろった場合用の区分。今回の気象庁連携では降雨終了時刻・警報/現地情報等が未取得のため、天気が良くても通常は「判断材料不足」になる。無理に緑表示にしない。
- 前日までの3日分の真夜中の24h降水観測が全て品質確認できた場合だけ、前日24時までの72h合計と直近連続降雨日数（最大3日）を参考表示する。移動する現在時刻を終端とした72hではない。欠測を0mmにしない。未来の雨量をmmに置き換えない。将来日の画面でもこの値は直近の観測であり、その候補日前の72h予測ではない。
- 乾燥時間は共通目安24時間、変更可能。ただし降雨終了時刻が不明なので現時点の画面では実際の乾燥時間を計算しない。24時間経てば安全・乾燥済みとはしない。
- 気温・湿度・風・日照・露点、警報・増水・凍結・アクセス規制は自動取得しない。未取得と明示する。確認前に安全判定に使わない。
- 出発の基準地点と平日/土日祝の移動時間上限は計画メモとして保存する。経路API未連携なので所要時間や移動可能範囲の自動判定はしない。出発地点はAIへ送らない。
- 土日祝の区分は内閣府の2026/2027年の祝日・休日を追加対象にする。曜日の指定も維持。2028年以降は一覧の更新が必要で、祝日を予測しない。
- ○△×? と説明文を併用。色だけで意味を伝えない。表示は地域予報に基づく計画補助で、岩の乾燥・登攀安全を保証しない。

## AIと利用枠

数値ルールが判定し、AIは同じ判定内での候補の比較順と既存理由の選択だけを行う。
AIの出力は候補IDと理由番号だけ。全候補が一度ずつ現れ、番号が元データ内か検証する。
画面の説明は選択された元の理由から構築し、AIの自由作文を表示しない。AIが見送りをおすすめに変更することはない。
不足データを外部検索・推測で補完しない。気象条件で差が付けられなければ元の順を保つ指示。

- Googleへ送る項目：岩場名、日付、予報発表時刻、判定と理由・不足情報、登録した岩場の特徴・活動時間帯、快適さ／完登重視の目的。
- 出発地点、身体情報、トレーニング記録、アカウントIDは送らない。ブラウザー/サーバー双方で許可項目だけを再構築。
- 岩場の特徴欄には個人情報を書かない。無料サービスでは入力・回答がGoogleの製品改善に使用され、人の確認対象となる場合があることを送信前に表示する。天気用の送信確認をAIコーチの同意で代用しない。
- Supabase Edge Function weather-advisorを経由。既存のGEMINI_API_KEY、GEMINI_MODEL、AI_ALLOWED_USER_IDS、AI_FREE_TIER_CONFIRMEDと無料モードの設定を再利用。キーはログ・ブラウザーへ出さない。
- 既存と同じ無料対象モデル一覧を使用。有料モードや別モデルへ自動切替しない。検索・Maps・外部ツールを呼ばない。
- 天気比較はサーバー側でユーザーごとに日本時間1日1回。失敗も含む。同じ日の同じ入力・予報・条件は保存済み結果を返す。条件変更後に以前の結果を最新として使わない。
- 月間上限は既存のAI_MONTHLY_LIMITとAI_GLOBAL_MONTHLY_LIMITの小さい値（既定30）で、AIコーチと天気の合計。既存AIコーチの個別上限も維持。両者の利用間隔も共有し、同じDBロックで同時実行の抜けを防ぐ。失敗や利用枠を手動リセットしない。
- Googleの枠はプロジェクト単位・モデル等で変動する。アプリの日付区切りJSTとGoogleのRPDリセット（太平洋時間）は別。アプリの1日1回はGoogleの利用可能枠を保証しない。
- ステータス確認は生成を行わない。自動再試行なし。上限・失敗・未配置でも数値判定と通常機能を利用できる。
- 比較入力は最大70候補・60KB、APIタイムアウト45秒、出力3500トークンまで。

## 配置

既存001〜003適用済みの環境で、202610310001_weather_advisor.sqlを一度適用する。
追加テーブルはRLS有効、本人は自分の比較結果のみ閲覧可能。書込み・予約・合計利用枠RPCはservice_role限定。
既存の記録・身体情報・設定行は更新しない。AIコーチの予約関数は共有月間枠と間隔の集計だけを拡張する。
既存AIコーチの合計枠取得もai_combined_usage RPCへ変更するため、SQL → 両Function → ブラウザー公開の順。

```powershell
npx.cmd supabase db query --linked --project-ref YOUR_PROJECT_REF --file supabase/migrations/202610310001_weather_advisor.sql
npx.cmd supabase functions deploy ai-coach --project-ref YOUR_PROJECT_REF
npx.cmd supabase functions deploy weather-advisor --project-ref YOUR_PROJECT_REF
```

秘密の再登録や課金設定の変更は不要。上記コマンドは本番の記録をサンプルにしてテストするものではない。
DBの適用状況・Function配置・ブラウザー配信確認と、実AI生成成功・iPhone実機確認は区別して報告する。
