# ログイン保持・再認証

## 方針

- 「この端末でログイン状態を保持する」は既定オフ。非保持はsessionStorage、保持はlocalStorage。SDKはカスタムStorageを使用し、プロジェクトごとに保存キーを分けます。
- 無操作30分、パスワードで認証してから最大7日。トークンの自動更新でauthenticatedAtを更新しません。
- 表示中の実行タイマー/回数式トレーニング/単独休憩タイマーは使用中と扱います。未完了のまま古くなった時間式タイマー、非表示の画面は免除しません。終了時は無操作猶予を改めて開始します。
- 7日の上限や認証失効はタイマー中でも適用。authLockで入力下書きと途中実績を保存し、タイマーを一時停止して画面の消灯抑制を解除します。
- appRootをhidden/inertにし、bodyに追加されたdialogも閉じます。期限を超えた後の最初のクリックで、期限を延長して操作を通すことはありません。
- SupabaseのgetUserで復元セッションの本人確認を行い、データ読み込み・初期化が終わってから画面を表示します。サインアウト/認証アカウント変更を監視し、非同期読み込みが遅れて到着しても旧画面を再表示しません。

## 保存と再開

認証情報とセッション方針はクラウドのアプリpayload/JSONバックアップには含めません。

| 保存キー | 内容 |
|---|---|
| `climbLogAuth:<project>:policy` | userId, remember, authenticatedAt, lastActivityAt, requiresReauth |
| `climbLogAuth:<project>:token` | SDKの認証セッション。選択したStorageにだけ保存 |
| `climbLogAuth:<project>:owner` | ブラウザー内で現在使用するアカウント。別アカウントのタブを非表示にするための識別 |
| `climbLogAuth:<project>:event` | 別タブにロックを伝える通知。トークンは含めない |
| `climbLogPendingState:<userId>` | payload, revision, baseUpdatedAt, savedAt。未同期の保留データ |

記録の書き込み時に保留データを作り、同期成功時は同じrevisionのものだけ除去します。同期中に追加された変更を成功通知で消しません。認証が必要な間はアプリからの保存・同期を止め、別アカウントとして送信しません。失効時に未保存のレコード入力は既存のInputDraftStoreへ、トレーニング実績はWorkoutDraftへ保存します。一般の設定画面にある未保存の自由入力すべてを自動保存する仕組みではありません。

再ログインでサーバー側のupdated_atが保留データの基点と一致すれば、端末データを復元し同期します。一致しない場合は自動上書きを行わず、端末/クラウド双方のJSONバックアップと、どちらを使うかの確認を表示します。この確認画面でも認証期限を確認します。端末優先を明示した場合はクラウドのpayloadを置き換えるため、必要なら先にバックアップしてください。

新しいSDKクライアントはログイン後にページを読み込み直して初期化します。別アカウントへの切替で前のアプリ状態を使い回しません。保留データと下書きは所有者ごとのキーを維持します。同じブラウザーの複数タブで異なるアカウントを同時使用する構成は採らず、所有アカウントが変わった古いタブはロックします。古いタブが新しいアカウントのトークンを除去しないよう、失効対象トークンを固定して扱います。

## 無料プランでの制限

これはアプリ側の再認証制御です。ブラウザー内のコードやStorageは利用者自身が改変可能であり、7日/30分をサーバー単独で強制する仕組みではありません。RLSは従来どおりauth.uid()とuser_idを照合します。Supabase標準のセッション期間・無操作タイムアウト設定はPro以上です。JWTを短くするだけで再ログインが必須になるわけでもありません。

期限検知時/手動ログアウト時はscope:'local'で現在のセッションの失効を要求し、自動更新を停止します。他端末をまとめてログアウトするglobalは使用しません。ネットワーク失敗時は端末のログイン情報を除去してロックを維持します。すでに発行されたJWTはその有効期限までサーバー側で有効になり得ます。

非保持モードのsessionStorageも、ブラウザーのタブ複製/復元機能によりコピー・復元されることがあります。通常の新規タブには引き継ぎませんが、OS・ブラウザーの全復元挙動までは保証しません。復元時にも30分/7日の期限を確認します。下書きと保留データは端末の平文Storageであり、暗号化保管庫ではありません。

旧保存キーの無期限ログインは移行せず、パスワードによるログインを一度求めます。変更は既存のデータベーススキーマやSupabase課金設定を変更しません。

公式資料: [Supabaseセッション](https://supabase.com/docs/guides/auth/sessions)、[JavaScript認証](https://supabase.com/docs/reference/javascript/auth)、[サインアウトのスコープ](https://supabase.com/docs/guides/auth/signout)。

## 検証

- `node --test tests/*.test.mjs`: 95ケース。方針の境界、タイマー免除、保持/非保持Storage、認証時刻の不変性、復元拒否、アカウント切替中の失効、SDK補助データ除去、既存の記録/タイマー/閲覧/AI開発中機能を検証。
- `node tests/browser/auth-session.mjs`: ローカルHTTPサーバーとモックAuth/DBを使用。PC1280px/スマホ390pxで誤パスワード、タブ終了/再読み込み、保持チェック、30分、7日、自動更新イベント、期限後クリックの拒否、下書き/実績復元、トレーニング中の無操作免除、未同期復元、競合選択、別アカウント分離、詳細dialogの非表示、複数タブでのログアウト、新しいアカウントを古いタブが失効させないことを確認。
- `workout.mjs`、`record-view.mjs`、`pwa.mjs`: 既存のトレーニング進行、閲覧/編集、PWAの回帰を確認。認証用メタデータや保留データは静的ファイルキャッシュには入りません。

実際のSupabase認証サーバーでのトークン失効、iPhone実機、全ブラウザーのセッション復元は未検証です。テスト用アカウントの秘密や本番データは使用していません。ブラウザーテストには既存と同じCLIMBLOG_PLAYWRIGHT_MODULE/CLIMBLOG_BROWSERを使用します。
