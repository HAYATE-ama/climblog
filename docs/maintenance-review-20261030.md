# 日常の記録操作の保守（2026-10-30）

## 対象と判断

現行ClimbLogのみを調査・変更した。昨日は実装前の調査までで、今回はその続きとして、利用頻度が高く変更リスクの小さい記録入力と保存結果の改善に絞った。全面的なデザイン刷新や新しい画面の追加は行っていない。AI生成機能は今回の対象外で、生成処理・モデル・同意・送信範囲・利用制限を変更せず、実AI APIも呼び出していない。

昨日の補助調査は利用制限で実行できなかったため、主担当が実装・検証を行った。本日は別のエージェントによる対象差分の限定レビューを実施し、公開を止める問題がないことを確認した。候補のアカウント分離、安全な文字列表示、固定フッター、保存通知の意味を独立確認した。

## 採用した改善

| 問題 | 変更前 → 変更後 | 維持すること |
|---|---|---|
| 長い入力画面では保存ボタンまでスクロールする必要がある | 末尾のみ → 下部に保存・閉じる操作を固定 | 既存の保存ボタンを移動。二重の保存操作を追加しない。件数表示、下書き、キーボード循環を維持 |
| 外岩の場所や課題名を繰り返し入力する | 毎回手入力 → 最近の岩場を最大3件提示。エリアと課題名に入力候補 | 自由入力を残す。岩場を選んでも他の入力やグレードは自動変更しない。名前を自動統合しない |
| 記録を保存しても、画面が閉じるだけで成功が分かりにくい | 閉じるのみ → 端末保存・更新と件数を短く表示 | クラウド同期済みとは断定しない。既存の同期表示を案内。8秒で消え、手動でも閉じられる |
| ジム設定の保存完了表示がすぐ消える | 表示後の再描画で消去 → 再描画の後に結果を表示 | 保存方式と設定の構造を維持。結果の読み上げを追加 |

候補はログイン中アカウントの既存記録から取得する。エリアは選択した岩場、課題名はさらに入力済みのエリアに絞る。候補用の新しい個人情報保存先・外部送信・データ移行は追加しない。ログアウト時は候補と保存通知を消去する。保存通知は次の記録入力開始時にも消し、以前の成功を今回の成功と混同させない。

## 比較して見送った案

- 大規模な画面刷新・フレームワーク追加：慣れた導線を変える負担に対して、今回の具体的な問題を解決する効果が小さい。
- 前回の外岩記録を自動コピー：異なる課題の結果・グレード・天気まで混ざる可能性があるため、名前の候補だけにした。
- 全ての警告・確認画面の一括置換：削除、復元、設定破棄などへの影響範囲が広い。今回は既存の確認を維持した。
- 同期方式・DB構造の変更：今回の操作性改善には不要。既存の競合保護とアカウント分離を維持した。
- 運動プログラム・重量の自動変更：今回の保守の範囲外。運動内容や効果の主張を変更していない。

## 検証

- 単体テスト283件成功。候補の並び、重複、岩場・エリアによる絞り込み、旧形式、元データを変更しないことを追加確認。
- 新規の画面試験：320 / 390 / 1280px、ライト・ダーク。固定保存ボタン、最近の岩場の選択とキーボード位置、文字列の安全表示、自由入力、追加・編集・一括保存、件数通知、ジム設定の保存表示、認証解除時の消去、横はみ出しを確認。高さ480pxでも入力欄が固定フッターに隠れないこと、入力エラー時に保存成功の通知を表示しないことも確認。
- 既存の画面試験9本成功：record-dialog、mobile-record-flow、historical-edit、record-view、settings-drawer、workout、auth-performance、auth-session、pwa-upgrade。
- 全てサンプルとモックで検証。本番の記録・身体情報・アカウントをテストで変更していない。秘密ファイルを閲覧・公開していない。
